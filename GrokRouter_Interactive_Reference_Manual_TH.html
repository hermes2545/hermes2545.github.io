GrokRouter คืออะไร?

คู่มือฉบับละเอียดสำหรับทำความเข้าใจ ติดตั้ง ใช้งาน ตรวจสอบ และย้อนกลับ GrokRouter โดยยึดสถานะต้นฉบับล่าสุดของ repository ณ 1 กันยายน 2026

ใช้ Grok Bot เหมือนเดิม
แต่เลือก “สมอง AI” ต่อ Bot ได้

GrokRouter ไม่ได้สร้าง UI ใหม่และไม่ได้ย้าย Computer/Files/Browser ไปอยู่กับ provider ภายนอก แต่ patch จุดเรียก inference ภายใน host ที่รองรับเท่านั้น

พื้นฐาน

แนวคิด: “Grok เป็นตัวควบคุม — Model เป็นตัวคิด”

จุดที่ทำให้ GrokRouter น่าสนใจไม่ใช่แค่การสลับโมเดล แต่คือการพยายามรักษา tool boundary และ permission behavior ของ Grok Bot เอาไว้

Control Plane

คำสั่ง /provider, /models, /reasoning, /doctor ถูก router จัดการก่อน model inference จึงให้ผลแบบ deterministic ไม่ใช่ปล่อยให้โมเดล “เดา” ว่าคำสั่งหมายถึงอะไร

Inference Plane

ข้อความสนทนาที่ไม่ใช่ control command จะถูกส่งไปยัง provider ที่ Bot นั้นเลือก จากนั้นคำตอบกลับเข้าช่องแชต Grok เดิม

Tool Plane

Provider ขอใช้ tool ได้เฉพาะ schema ที่ Grok ส่งมาใน turn นั้น และ Grok เป็นผู้ execute พร้อมใช้ permission behavior ของตัวเอง

Recovery Plane

ก่อน patch จะมี verified stock backup; ระบบมี disable, repair, restore และตรวจ exact hash/source anchors เพื่อไม่ patch host ที่ไม่รู้จัก

หลักการสำคัญ 5 ข้อ

  1. Version-gated: รองรับ Grok Bot build ที่ระบุอย่างเจาะจง ไม่ wildcard.
  2. Per-Bot state: provider/model/reasoning/thread state ถูกแยกตาม Bot.
  3. Tool authority comes from Grok: โมเดลภายนอกสร้างสิทธิ์ tool เพิ่มเองไม่ได้.
  4. Fail closed: hash, source anchor, credential shape หรือ terminal verification ผิด → หยุด.
  5. Reversible: มี stock backup และ restore path ที่ตรวจสอบก่อนแทนที่ไฟล์.

Pre-flight checklist

ถ้า Grok Bot อัปเดตเองจน version ไม่ตรง
อย่าฝืนติดตั้งด้วยการแก้ manifest หรือเปิด override แบบสุ่ม หลักการของโปรเจกต์คือ unknown host ต้อง fail closed จนกว่าจะมี manifest/hash/anchor ใหม่และผ่าน acceptance gate
ติดตั้ง

ติดตั้ง GrokRouter บน macOS แบบที่แนะนำ

เส้นทางที่ repository แนะนำคือ build native app จาก source ที่ดาวน์โหลดเอง แล้วติดตั้งไว้ใน personal Applications folder

  1. ติดตั้งและเปิด Grok Bot 0.30.0

    ให้แอปอยู่ใน /Applications เปิดหนึ่งครั้ง เลือก Bot และกด Open computer ให้แน่ใจว่าทำได้

  2. Download repository เป็น ZIP

    ที่ GitHub เลือก Code → Download ZIP แล้วแตกไฟล์

  3. Double-click Install GrokRouter.command

    script จะ build native Swift app จาก source, verify app, ติดตั้งไปที่ ~/Applications/GrokRouter.app และเปิดให้

  4. เปิด GrokRouter และเลือก provider

    เปิด/ปิด Codex SDK และ OpenRouter, เลือก default provider/model ตามต้องการ

  5. กรอก OpenRouter key ถ้าใช้

    key ถูกส่งเข้าสู่ Grok Bot protected Secrets store แล้ว field ใน installer จะถูก clear

  6. กด Install Router

    installer ตรวจ exact app/version, เปิด diagnostic แบบ loopback, backup stock host และ patch เฉพาะเมื่อ hash/anchors ตรง

  7. ถ้าระบบขอ Bot computer

    กลับไป Grok Bot → เลือก Bot → Open computer แล้วคงทั้ง Grok Bot และ GrokRouter เปิดไว้ระหว่าง install

  8. ถ้าเปิด Codex

    ใช้ปุ่ม Codex sign-in และทำ device sign-in ที่แสดงใน Bot terminal

  9. สร้าง Bot ใหม่เพื่อทดสอบ

    อย่าใช้แค่ Bot เก่ามายืนยัน เพราะ acceptance ของโปรเจกต์เน้น genuinely fresh Bot

Apple Command Line Tools
ถ้ายังไม่มี ระบบ macOS อาจเสนอให้ติดตั้ง Command Line Tools ก่อน ให้ติดตั้งให้เสร็จแล้วเปิด Install GrokRouter.command ซ้ำ

ระบบภายใน

หนึ่งข้อความเดินทางอย่างไร

เข้าใจ flow นี้แล้วจะเห็นชัดว่า Router ไม่ใช่ผู้ execute computer tool เอง

Normal conversation turn

  1. Grok Bot สร้าง session พร้อม conversation/system instructions/tools ที่มีใน turn.
  2. host adapter ตรวจ provider.json; ถ้า routing disabled → stock inference.
  3. ถ้า enabled → launch Node runtime และส่ง sanitized JSON ผ่าน stdin.
  4. runtime โหลด provider/model ของ Bot นั้น.
  5. Codex resume SDK thread หรือ OpenRouter รับ Chat Completions request.
  6. text response ถูก wrap กลับเข้า Grok delivery mechanism.

Replay & completion handling

runtime มี replay-control metadata และ per-Bot lock เพื่อกัน host replay ทำให้ inference ซ้ำ หลัง model switch/reset จะเพิ่ม thread epoch เพื่อกัน late response เก่ากลับมาเขียน state ทับการเปลี่ยนใหม่

ระบบภายใน

Per-Bot State, Identity และ Concurrency

การสลับ provider/model ไม่ใช่ global toggle แต่ผูกกับ stable identity ของ Bot และมีการเขียน state แบบ atomic

State ต่อ Bot

provider, model, reasoning, provider thread reference และ replay-control metadata

Stable identity

Bot ID มี priority เหนือ agent/conversation IDs จึงรักษา choice เดิมเมื่อ Bot ไปอยู่ใน channel

Atomic update

เขียน state ภายใต้ short per-Bot lock และใช้ thread epoch กัน response เก่ามาย้อนการตั้งค่า

Installer access

  • Mac validate /Applications/Grok Bot.app
  • diagnostic port bind เฉพาะ 127.0.0.1
  • operate visible noVNC Bot computer
  • write ใต้ /home/box/sand-data/grokbot-router
  • backup/replace /home/box/sand-host/host-main.cjs

OS permissions

ข้อจำกัด

สิ่งที่ GrokRouter ยังไม่ใช่ และ Claim ที่ต้องระวัง

ส่วนนี้สำคัญพอๆ กับวิธีติดตั้ง เพราะ Router อยู่บน implementation detail ของ proprietary Grok Bot host

ไม่ใช่ official xAI feature

project ระบุชัดว่า unofficial, independent และไม่ affiliated กับ xAI, X, OpenAI, Anthropic หรือ OpenRouter.

ไม่รองรับ version แบบกว้าง

ปัจจุบัน pin กับ Grok Bot 0.30.0. Unknown builds ถูก reject แทนการเดา.

ไม่ทำให้ provider มี tool authority เพิ่ม

ถ้า Grok ไม่ส่ง schema ของ Shell/Computer/Sub-agent มาใน turn นั้น Router ต้องไม่ fabricate สิทธิ์.

ไม่ใช่ privacy isolation layer

routed model ต้องได้รับ conversation/attachment/tool results ที่จำเป็นต่อ turn.

ไม่ควรใช้ Windows claim เต็ม

source/packaging/CI ผ่าน แต่ native live cycle ยัง pending ตาม test matrix.

ไม่ใช่ redistribution-friendly OSS license

อนุญาต personal non-commercial build/use แต่ห้าม redistribute/publish/incorporate into product โดยไม่ได้รับ permission.

Rule of thumb
ถ้าคุณอธิบายความสามารถแล้วประโยคนั้นฟังดูแรงกว่าคำใน Test Matrix ให้ลด claim ลงมาอยู่ที่หลักฐานจริง

source เปิดให้ดูและ build ใช้ส่วนตัวได้ แต่ข้ออนุญาตไม่เท่ากับ open-source license แบบแจกต่อได้อิสระ

สิทธิ์ที่ให้

  • copy/modify/build/use สำหรับ personal, non-commercial purposes
  • ทำ private custom build บนเครื่องของตัวเอง
