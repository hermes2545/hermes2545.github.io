Agent Reach คืออะไร

Agent Reach คือ “ชั้นความสามารถ” (capability layer) ที่ติดตั้งให้ AI Agent ของคุณอ่านและค้นหาข้อมูลจากอินเทอร์เน็ตได้จริง — ทั้ง Twitter, Reddit, YouTube, GitHub, Facebook, Instagram, 小红书 และอื่น ๆ รวม 15 แพลตฟอร์ม โดยไม่ต้องเสียค่า API

ปัญหาที่มันแก้

AI Agent เขียนโค้ด แก้เอกสาร จัดการโปรเจกต์ได้ดี แต่พอสั่งให้ “ไปหาข้อมูลในเน็ต” มักจะทำไม่ได้ เพราะแต่ละแพลตฟอร์มมีกำแพงคนละแบบ:

สิ่งที่คุณอยากให้ Agent ทำปัญหาเดิม
สรุปคลิป YouTube นี้ให้หน่อยดึง subtitle ไม่ได้
ดูว่าคนบน Twitter พูดถึงสินค้านี้ยังไงTwitter API ต้องจ่ายเงิน
ไปดู Reddit ว่ามีใครเจอ bug เดียวกันไหมโดน 403 บล็อก IP เซิร์ฟเวอร์
ดูรีวิวสินค้าบน 小红书 / Instagramต้องล็อกอินถึงจะเปิดได้
อ่านหน้าเว็บนี้ให้หน่อยได้ HTML tag กลับมาเป็นพรืด อ่านไม่รู้เรื่อง
สรุปวิดีโอ Bilibiliyt-dlp โดนระบบกันบอทของ B站 บล็อกหมด (412)

ทุกอย่างนี้ “ทำได้” แต่ต้องไปหาเครื่องมือ ติดตั้ง ตั้งค่า ทีละแพลตฟอร์มเอง Agent Reach ย่อทั้งหมดเหลือ ประโยคเดียว

ติดตั้งใน 3 ขั้น

คุณไม่ต้องพิมพ์คำสั่งติดตั้งเอง — วิธีมาตรฐานคือ ส่งลิงก์คู่มือติดตั้งให้ AI Agent แล้วให้มันทำเอง

  1. คัดลอกประโยคนี้ไปวางในแชตกับ Agent

    คำสั่งติดตั้ง (ภาษาไทย)
    ช่วยติดตั้ง Agent Reach ให้หน่อย โดยอ่านและทำตามคู่มือนี้:
https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md

ข้อกำหนด:
- ให้ตรวจสอบ (check-only) ก่อน แล้วสรุปให้ฉันดูว่าจะติดตั้งอะไรบ้าง
- ห้ามใช้ sudo และห้ามสร้างไฟล์ใน workspace ของโปรเจกต์
- รอฉันอนุมัติก่อนค่อยรันโหมด --system
    ต้นฉบับภาษาจีนคือ 帮我安装 Agent Reach：<URL> — ใช้ประโยคไทยด้านบนได้ผลเหมือนกัน เพราะ Agent อ่านคู่มือปลายทางเป็นภาษาอังกฤษอยู่แล้ว

  2. Agent จะถามว่าอยากได้ช่องทางไหนเพิ่ม

    ค่าเริ่มต้นจะเปิดเฉพาะช่องที่ไม่ต้องล็อกอิน (เว็บ, YouTube, GitHub, RSS, Exa, V2EX และ B站 แบบพื้นฐาน) ส่วนช่องที่ต้องล็อกอิน — Twitter, Reddit, Facebook, Instagram, 小红书 — จะขึ้นเป็นเมนูให้เลือก เลือกเฉพาะที่ใช้จริง (ดูบทที่ 05)

  3. ตรวจผลด้วย doctor

    ตรวจสถานะทุกช่องทาง
    agent-reach doctor
    เติม --json ถ้าอยากได้ผลแบบเครื่องอ่าน (จะเห็นฟิลด์ active_backend ของแต่ละช่อง)

--env รับค่า local / server / auto · --safe มีผลเท่ากับค่าเริ่มต้น (มีไว้เพื่อความเข้ากันได้)

info
Agent Reach ยังไม่รู้จัก Hermes โดยตรง มันจะเขียน skill ลงโฟลเดอร์กลาง ~/.agents/skills/agent-reach — เราแค่ชี้ให้ Hermes มาอ่านที่นั่น
1) ติดตั้ง skill ลงโฟลเดอร์กลาง
agent-reach skill --install
ls ~/.agents/skills/agent-reach
2) วิธี ก — คัดลอกเข้าโฟลเดอร์ skill ของ Hermes (ตรงไปตรงมาที่สุด)
mkdir -p ~/.hermes/skills
cp -r ~/.agents/skills/agent-reach ~/.hermes/skills/agent-reach
ls ~/.hermes/skills/agent-reach
ต้องคัดลอกทั้งโฟลเดอร์ ไม่ใช่แค่ SKILL.md เพราะมีโฟลเดอร์ references/ ที่เก็บคำสั่งละเอียดของแต่ละแพลตฟอร์ม
2) วิธี ข — ให้ Hermes อ่านจากโฟลเดอร์กลางแทน (ไม่ต้องคัดลอกซ้ำเวลาอัปเดต)
# แก้ ~/.hermes/config.yaml
skills:
  external_dirs:
    - ~/.agents/skills
3) ตรวจว่า Hermes เห็น skill แล้ว
hermes skills list | grep -i reach
  • Hermes ต้องเปิดสิทธิ์ terminal / execute_code ไว้ ไม่งั้นจะรัน agent-reach, opencli, yt-dlp ไม่ได้เลย
  • ถ้าคุณรัน Hermes บน WSL2 ให้ติดตั้งฝั่ง Linux ทั้งหมด และจำไว้ว่า backend ที่ต้องใช้ Chrome (OpenCLI) ต้องมี Chrome ที่ Hermes เข้าถึงได้จริง
  • ถ้า Hermes รันบนเซิร์ฟเวอร์ที่ไม่มีหน้าจอ ให้ข้าม OpenCLI แล้วใช้เส้นทาง Cookie-Editor แทน (บทที่ 06)

AGENT-REACH OPERATING SPEC v1.5.0
# AGENT REACH — OPERATING SPEC (v1.5.0)

ROLE
  Agent Reach is a capability layer: it SELECTS, INSTALLS, HEALTH-CHECKS and
  ROUTES upstream tools. It is NOT a wrapper. You (the agent) call the upstream
  tools directly.

STANDING RULES
  1. Before acting on a multi-backend or login-backed platform
     (xiaohongshu, reddit, bilibili, twitter, facebook, instagram, xueqiu):
     run `agent-reach doctor --json` and use the populated `active_backend`.
     `active_backend: null` means Doctor deliberately skipped a live probe —
     it does NOT mean no backend exists.
  2. Announce what you use: "using agent-reach, platform X via backend Y".
  3. On failure, follow the documented retry chain. Never invent commands.
  4. Success = non-empty real content. Exit code 0 with empty fields is failure.
  5. For broad research: combine Exa (web) + Twitter/Reddit (discussion)
     + Xiaohongshu/Bilibili (Chinese perspective), collect in parallel,
     then synthesize.
  6. After a substantial multi-platform task, run `agent-reach check-update`
     once. Never interrupt the task to update. Never nag twice.

BOUNDARIES (hard)
  - No sudo unless the user explicitly approved.
  - Do not modify system files outside ~/.agent-reach/.
  - Do not install packages not listed in the official install guide.
  - Do not disable firewalls or security settings.
  - Do not clone repos, create files, or run commands in the agent workspace.
    Use /tmp/ for temp files and ~/.agent-reach/ for persistent data.
  - Never log the user into XiaoHongShu and never read its browser cookies.
    OpenCLI may use ONLY an existing Chrome session the user controls.
  - Twitter cookies saved via `agent-reach configure twitter-cookies` are for
    doctor's presence check only. Before running `twitter`, explicitly provide

  - Read-only by default. Do not post, comment, or like.

CRITICAL CAVEATS
  - NEVER use yt-dlp for Bilibili (412 blocked). yt-dlp is YouTube only.
  - XiaoHongShu requires xsec_token: search first, then read the full URL.
  - Rate limit XiaoHongShu to one call every 2-3 seconds or hit CAPTCHA.
  - Instagram/Facebook 429 => have the user re-login in Chrome, slow down.
  - Reddit has NO zero-config path. Login is mandatory.
  - Xueqiu HTTP 400 = cookie/session problem, not a missing ticker.
  - Cookie auth carries ACCOUNT BAN RISK. Recommend a dedicated burner account.
