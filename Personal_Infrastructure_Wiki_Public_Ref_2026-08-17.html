Purpose

This document describes how to build a durable knowledge system for personal infrastructure. Instead of forcing an AI assistant to remember every device, automation, server, VM, and NAS detail in short memory, the system separates knowledge into short memory, a markdown wiki, YAML inventories, and reusable runbooks.

Public-safe version: this file is generic by design. It contains no real site names, people names, private directories, entity IDs, IP addresses, domains, account IDs, bot tokens, passwords, or secret values.

Why this matters

Personal infrastructure grows quickly. Smart-home automations, network devices, servers, VMs, containers, NAS shares, backups, and alerts become too detailed for one chat or a small memory block. A structured wiki lets the AI assistant load the right knowledge only when needed.

Who can use it?

  • Home Assistant users
  • Homelab builders
  • NAS and backup administrators
  • Self-hosters
  • People running AI assistants for home operations
  • Anyone who wants infrastructure knowledge to persist across sessions

The four-layer model

1Short memory for routing facts
2Markdown wiki for durable knowledge
3YAML inventory for precise maps
4Skills/runbooks for repeatable work

Short Memory

Use memory only for compact facts the assistant needs every time: the active profile, safety preferences, common aliases, and pointers to the wiki. Do not store large maps or secrets here.

Markdown Wiki

Use the wiki for durable explanations: topology, architecture, devices, automations, services, alerts, decisions, incidents, and operational notes.

YAML Inventory

Use YAML for machine-readable facts: devices, entity placeholders, host lists, VM lists, containers, NAS shares, backup jobs, alert routes, and service dependencies.

Skills / Runbooks

Use runbooks for procedures: add a device, add an alert route, debug snapshots, restart a service, rotate secrets, recover a failed update, or restore from backup.

How to use it

  1. Create the wiki skeleton and schema.
  2. Add only non-secret system facts and placeholder examples at first.
  3. Move frequently used details into YAML inventories.
  4. Write runbooks for repeated operations.
  5. Tell the AI assistant: read memory pointers, then the wiki index, then the relevant page and inventory before acting.
  6. After each durable change, update the wiki, inventory, and log.
  7. Before public export, run a redaction scan.

What to never publish

Never publish real names, home/site names, private URLs, internal IP addresses, domains, tokens, passwords, private keys, secret hashes, local paths, account IDs, or real smart-home entity IDs. Use placeholders and [REDACTED].
