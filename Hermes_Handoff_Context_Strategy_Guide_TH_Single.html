คู่มือ Handoff & Context Strategy สำหรับ Hermes Agent

คู่มือฉบับ Public-safe สำหรับการทำงานกับ Hermes Agent ในบทสนทนาระยะยาว การใช้ /new หลาย chat surfaces, bots, profiles, project folders, skills, memory และ handoff files โดยไม่สูญเสีย context สำคัญ

Public-safe version
คู่มือนี้ใช้ generic placeholders เท่านั้นโดยตั้งใจ และไม่มี private names, real device names, entity IDs, URLs, IP addresses, tokens, emails, house-specific details หรือ account-specific identifiers

วัตถุประสงค์

เอกสารนี้อธิบายวิธีทำงานกับ Hermes Agent ในสถานการณ์ที่บทสนทนายาว มีการเริ่ม /new session ใช้งานผ่าน chat surfaces ที่แตกต่างกัน ใช้ bots หรือ profiles หลายตัว รวมถึงการจัดการ project folders, skills, memory และ handoff files โดยไม่ทำให้ context สำคัญสูญหาย

แนวคิดหลักคือ:

อย่าพยายามให้ Hermes เก็บรายละเอียดทุกอย่างไว้ใน short-term chat context หรือ permanent memory แต่ให้สร้าง layered context system ที่ทำให้ Hermes รู้เสมอว่าควรไปค้นข้อมูลจากที่ใด
text
Short-term chat context = current reasoning and active discussion
Persistent memory       = compact pointers and durable preferences
Project files           = current state, TODOs, decisions, verification logs
Wiki / knowledge base    = durable system knowledge and reference material
Skills                  = repeatable procedures and workflows
Session search          = recovery from older conversations
Handoff summaries        = clean transfer between sessions

1เหตุผลที่ Hermes อาจ “ลืม” หลังใช้ /new

เมื่อเริ่ม /new ระบบจะสร้าง conversation context ใหม่ แม้ session ใหม่นั้นอาจยังเข้าถึง tools เช่น memory, skills, files, wiki และ session search ได้ แต่รายละเอียดทั้งหมดจาก chat ก่อนหน้าจะไม่ได้ถูกโหลดเข้าสู่ working context ของ model โดยอัตโนมัติ

พฤติกรรมนี้เป็นเรื่องปกติและตั้งใจออกแบบไว้ เพื่อให้ session ทำงานได้เร็วขึ้น ประหยัดกว่า และ reasoning ได้ง่ายขึ้น

สิ่งที่โดยทั่วไปยังคงอยู่ข้าม sessions

  • Persistent memory
  • User profile preferences
  • Skills
  • Files on disk
  • Project context files เช่น .hermes.md หรือ AGENTS.md
  • Wiki pages
  • Session transcripts ที่เข้าถึงได้ผ่าน session search
  • Cron jobs หรือ durable background jobs
  • External system state เช่น repositories, dashboards, documents และ APIs

สิ่งที่อาจไม่ถูกเก็บต่อโดยอัตโนมัติ

  • Full chat history จาก session ล่าสุด
  • Temporary reasoning steps
  • Tool outputs ถ้าไม่ได้บันทึกไว้ที่อื่น
  • สถานะงานปัจจุบันที่แน่นอน หากไม่ได้เขียนลงไฟล์
  • การตัดสินใจที่คุยกันแบบไม่เป็นทางการใน chat แต่ไม่ได้บันทึก
  • รายละเอียดที่ฝังอยู่ใน transcript ยาว ๆ โดยไม่มี searchable summary

กฎใช้งานจริง

ก่อนจบหรือ reset session ที่ยาว ควรบันทึกสถานะที่มีประโยชน์ไว้ในพื้นที่แบบ durable

ใช้ prompt นี้:

text
Before we start a new session, create a handoff summary with:
- goal
- current status
- files changed
- commands run
- verification results
- unresolved issues
- next exact steps
- assumptions and constraints
Save it to STATUS.md and also provide a copy-paste version.

2Five-layer Context Strategy

Layer 1: Current chat context

เหมาะสำหรับ:

  • Active conversation
  • Immediate reasoning
  • Back-and-forth debugging
  • Clarifications
  • Short-term task execution

ไม่ควรพึ่งพาสำหรับ:

  • Multi-day project state
  • Long-term knowledge
  • รายละเอียดที่ต้องอยู่รอดหลัง /new
  • Critical system mappings หรือ procedures

Best practice:

text
If this matters tomorrow, write it down outside the chat.

Layer 2: Persistent memory

Memory ควรเก็บ facts ที่กระชับและคงทน ซึ่งช่วยลดการอธิบายซ้ำ

ตัวอย่าง memory ที่ดี:

text
The user prefers concise status replies in Thai.
text
The main infrastructure knowledge base is stored in a local wiki under a known root path.
text
A specific automation bot uses a separate Hermes profile from the main assistant.

ตัวอย่าง memory ที่ไม่ดี:

text
Yesterday the dashboard script failed on line 123.
text
The current task is half done and needs command X next.
text
A temporary file was created at /tmp/example-123.

เหตุผลที่ตัวอย่างเหล่านี้ไม่เหมาะ:

  • ข้อมูลล้าสมัยเร็ว
  • ใช้พื้นที่ memory ที่มีจำกัด
  • อาจทำให้ future sessions สับสน
  • เหมาะกับการเก็บใน STATUS.md, VERIFY.md หรือ project log มากกว่า

Prompt สำหรับบันทึก memory

text
Please remember this as a durable preference/fact: [short fact].

Prompt เพื่อหลีกเลี่ยง memory pollution

text
Do not save this to memory. Put it in the project STATUS.md instead.

Layer 3: Project folder

สำหรับงานระยะยาว ให้สร้าง project folder และเก็บ state files ไว้ภายใน

โครงสร้างแนะนำ:

text
project-name/
  .hermes.md
  STATUS.md
  TODO.md
  DECISIONS.md
  VERIFY.md
  CHANGELOG.md
  scripts/
  docs/
  references/
  artifacts/

หน้าที่ของแต่ละไฟล์

FilePurpose
.hermes.mdProject-specific instructions และ stable rules
STATUS.mdCurrent project state และ next steps
TODO.mdTask list, backlog, priorities
DECISIONS.mdImportant decisions และเหตุผล
VERIFY.mdTest results, commands run, proof of completion
CHANGELOG.mdHuman-readable history ของ major changes
scripts/Reusable scripts ที่ Hermes หรือคนใช้งาน
docs/Project documentation
references/Supporting reference material
artifacts/Generated files, reports, screenshots, exports

Minimal project starter

คัดลอกข้อความนี้ไปไว้ใน project folder ใหม่

markdown
# Project Context

## Project goal
Describe the goal in one or two paragraphs.

## Important constraints
- Do not expose secrets.
- Do not publish private identifiers.
- Verify changes before reporting success.
- Prefer durable files over relying on chat memory.

## Key files
- STATUS.md: current state and next steps
- TODO.md: task list
- DECISIONS.md: decisions and rationale
- VERIFY.md: commands run and verification results

## Workflow
1. Read STATUS.md before starting.
2. Read DECISIONS.md before changing direction.
3. Update VERIFY.md after tests or checks.
4. Update STATUS.md before ending the session.
5. If a reusable workflow is discovered, turn it into a skill.

Layer 4: Wiki หรือ knowledge base

ใช้ wiki สำหรับ durable knowledge ที่กว้างกว่า project เดียว

เนื้อหาที่เหมาะกับ wiki:

  • System architecture
  • Device หรือ service inventories
  • Naming conventions
  • Operational runbooks
  • Common troubleshooting notes
  • Public-safe documentation
  • Cross-project knowledge

โครงสร้างแนะนำ:

text
wiki/
  index.md
  systems/
    overview.md
    services.md
    network.md
  automation/
    dashboards.md
    devices.md
    scenes.md
  hermes/
    profiles.md
    bots.md
    toolsets.md
    troubleshooting.md

Wiki index template

markdown
# Knowledge Base Index

## Purpose
This wiki stores durable context that should survive across sessions.

## Main sections
- systems/: architecture and service inventory
- automation/: automations, dashboards, and device categories
- hermes/: profiles, bots, toolsets, and operating notes

## Rules
- Keep secrets out of the wiki.
- Use placeholders for public-safe pages.
- Link to project folders for active work state.
- Keep long-term facts here; keep temporary progress in STATUS.md.

Layer 5: Skills

Skills คือ reusable procedures ไม่ใช่เพียง notes แต่เป็น operational playbooks

ใช้ skills สำหรับ:

  • Repeated troubleshooting workflow
  • Deployment procedure
  • Dashboard update process
  • Document generation process
  • QA checklist
  • Known multi-step integration

ไม่ควรใช้ skills สำหรับ:

  • One-time status updates
  • Temporary TODOs
  • Personal secrets
  • Large raw data dumps

Skill creation prompt

text
Please save the workflow we just used as a skill. Include:
- when to use it
- prerequisites
- exact steps
- commands or tools to run
- verification steps
- common pitfalls
- what not to do

Skill update prompt

text
The skill we loaded is missing an important pitfall we discovered. Patch the skill now before finishing.

3Handoff Strategy

Handoff คือ summary ที่กระชับแต่ครบถ้วน ทำให้ fresh session สามารถทำงานต่อได้โดยไม่ต้องเดา

ใช้ handoff เมื่อ:

  • กำลังจะใช้ /new
  • Conversation ยาวมากแล้ว
  • กำลังสลับจาก bot/profile หนึ่งไปอีกตัว
  • กำลังส่งมอบงานจาก agent หนึ่งไปอีก agent
  • ต้องการรักษาสถานะปัจจุบันแบบ exact
  • Task ใช้เวลาหลายวัน

Handoff template

markdown
# Handoff Summary

## Project
Project name or short description.

## Goal
The final outcome we are trying to achieve.

## Current status
What is true right now.

## What changed in this session
- Change 1
- Change 2
- Change 3

## Files created or modified
- `path/to/file`: why it matters
- `path/to/another-file`: why it matters

## Commands or tools run
```bash
command example here
```

## Verification performed
- Check 1: result
- Check 2: result
- Check 3: result

## Known issues
- Issue 1
- Issue 2

## Assumptions
- Assumption 1
- Assumption 2

## Security and privacy notes
- Do not expose secrets.
- Do not include private identifiers in public artifacts.
- Use placeholders when creating public documentation.

## Next exact steps
1. Read this handoff.
2. Read project context files.
3. Run the next command or perform the next action.
4. Verify the result.
5. Update STATUS.md and VERIFY.md.

## Suggested prompt for the next session
```text
Continue this project from the handoff below. First summarize the current state, then inspect the referenced files, then proceed with the next exact steps. Do not assume missing details; read the files or ask.

[PASTE HANDOFF HERE]
```

4การเริ่ม New Session อย่างมีประสิทธิภาพ

Bad prompt:

text
Continue from before.

Better prompt:

text
Continue the project from the handoff below. Read STATUS.md and VERIFY.md first. Then summarize the current state before taking action.

[PASTE HANDOFF]

Best prompt:

text
Continue the project in this folder:
/path/to/project

First read:
1. .hermes.md
2. STATUS.md
3. DECISIONS.md
4. VERIFY.md

Then:
- summarize the current state
- identify the next exact step
- perform the step
- verify the result
- update STATUS.md and VERIFY.md before finishing

สำหรับงานแบบ public-safe ให้เพิ่ม:

text
This output is for public distribution. Do not include personal names, real device names, entity IDs, URLs, IP addresses, tokens, account identifiers, private paths, or any details that can identify a person, home, or organization. Use generic placeholders only.

5Profile และ Bot Strategy

Hermes สามารถรันหลาย profiles หรือ bots ได้ และ bot ใหม่อาจไม่มี tools, memory, skills หรือ config แบบเดียวกับอีก bot

ควรตรวจให้ชัดเจนเสมอว่า:

  • Profile ใด active อยู่?
  • ใช้งานผ่าน platform ใด?
  • Bot ใดกำลังรับ message?
  • Toolsets ใดถูก enable สำหรับ profile และ platform นั้น?
  • Bot มี terminal, file, browser, code execution, Home Assistant, email หรือ tools อื่นที่งานนี้ต้องใช้หรือไม่?
  • หลังเปลี่ยน tools จำเป็นต้อง reset session หรือไม่?

Generic diagnostic prompt

text
Check which Hermes profile and platform this bot is using. Then list the enabled toolsets for this platform. Compare them with the tools needed for the task. Do not modify config by editing files directly; use Hermes CLI commands where appropriate.

Toolset troubleshooting pattern

text
If a tool is missing:
1. Identify the active Hermes profile.
2. Identify the platform, such as telegram, cli, api_server, or desktop.
3. Check enabled toolsets for that platform.
4. Enable the required toolset using Hermes CLI.
5. Reset the session or restart the gateway if required.
6. Verify the tool appears in a new session.

Generic command pattern

bash
HERMES_HOME=/path/to/profile hermes tools enable --platform <platform> <toolset-name>

ตัวอย่างด้วย placeholders:

bash
HERMES_HOME=/path/to/profile hermes tools enable --platform telegram terminal code_execution
bash
HERMES_HOME=/path/to/profile hermes tools enable --platform api_server file terminal code_execution
Important
Tool changes โดยทั่วไปจะไม่ปรากฏใน active conversation เดิม ให้เริ่ม new session หรือ reset session หลังเปลี่ยน toolsets

6Public-safe Documentation Strategy

เมื่อสร้าง material สำหรับ public sharing ห้ามใส่ข้อมูลต่อไปนี้:

  • Real personal names
  • Private email addresses
  • Real home names
  • Real device names
  • Entity IDs
  • Internal URLs
  • IP addresses
  • Hostnames
  • API tokens
  • Passwords
  • Account IDs
  • Chat IDs
  • Bot usernames
  • File paths ที่เปิดเผย identity
  • Screenshots ที่มี private data
  • House-specific floor plans หรือ layouts

<ENTITY_ID>

Public-safe instruction block

คัดลอกข้อความนี้ไปใส่ใน prompt เมื่อต้องการ:

text
Public-safe output required. Use generic examples only. Do not include personal details, real device names, entity IDs, URLs, IP addresses, tokens, passwords, account identifiers, bot usernames, chat IDs, local paths, or anything that can identify a person, home, organization, or deployment. Replace all such details with placeholders.

7Recommended Operating Playbooks

Playbook A: Long-running project

text
1. Create a project folder.
2. Add .hermes.md with project rules.
3. Add STATUS.md, TODO.md, DECISIONS.md, VERIFY.md.
4. Start every session by reading those files.
5. End every session by updating STATUS.md and VERIFY.md.
6. Store reusable procedures as skills.
7. Store broad durable facts in the wiki.
8. Store only compact pointers and preferences in memory.

Playbook B: Before /new

text
1. Ask Hermes to summarize the current state.
2. Ask Hermes to write or update STATUS.md.
3. Ask Hermes to write or update VERIFY.md.
4. Ask Hermes to produce a copy-paste handoff.
5. Start the new session with that handoff.

Playbook C: After /new

text
1. Paste the handoff.
2. Tell Hermes where the project folder is.
3. Tell Hermes to read .hermes.md, STATUS.md, DECISIONS.md, VERIFY.md.
4. Ask Hermes to summarize before acting.
5. Let Hermes continue only after it has grounded itself in the files.

Playbook D: Repeated workflow

text
1. Complete the workflow once.
2. Verify that it works.
3. Ask Hermes to convert the workflow into a skill.
4. Next time, explicitly ask Hermes to load and follow that skill.
5. If the skill is wrong or incomplete, patch it immediately.

Playbook E: Public artifact

text
1. State that the output is public-safe.
2. Forbid private identifiers explicitly.
3. Ask Hermes to use placeholders.
4. Ask Hermes to inspect the final output for accidental private data.
5. Only then export or send the artifact.

10Core Principle

วิธีที่เชื่อถือได้มากที่สุดในการป้องกัน context loss ไม่ใช่การบังคับให้ context ทั้งหมดอยู่ใน model แต่คือการสร้าง durable trail ที่ Hermes สามารถกลับมาอ่านได้

ใช้ mental model นี้:

text
If Hermes needs it only now, keep it in chat.
If Hermes needs it next session, write it to STATUS.md.
If Hermes needs it across projects, write it to the wiki.
If Hermes needs to do it repeatedly, make it a skill.
If Hermes needs to remember a stable preference, save it to memory.
If Hermes needs to recover an old discussion, use session search.

แนวทางนี้ทำให้ Hermes มีความน่าเชื่อถือมากขึ้นเมื่อทำงานข้าม /new, ใช้หลาย bots, ใช้ profiles ที่แตกต่างกัน, ทำงานใน long projects และสร้าง public-safe documentation workflows
