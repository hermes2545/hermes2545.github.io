คู่มือใช้งานจริงสำหรับคนงบ Token จำกัด

คู่มือประหยัด Token สำหรับ Hermes Desktop: ตั้งค่าให้คุ้ม ใช้งานได้หลายงาน งบไม่บาน

แนวทางจัดโมเดล, tools, context, workflow และ prompt ให้ Hermes Desktop ใช้งานได้หลายงานโดยไม่เผา token เกินจำเป็น เหมาะสำหรับคนที่ใช้ Gemini Flash / DeepSeek Flash เป็น daily driver แล้วค่อยขยับไปโมเดลแพงเฉพาะงานยาก

1ใช้โมเดลถูกเป็น default แล้วค่อย switch ตอนงานยาก
2ปิด tool/schema ที่ไม่ได้ใช้ เพราะเป็น hidden token cost
3คุม context ด้วย session สั้น, summary checkpoint และ targeted reading
4แยก profile ตามงานเพื่อไม่แบกความสามารถเกินจำเป็น

ภาพรวมแนวคิด: ลด Token โดยไม่ลดคุณภาพงาน

การประหยัด token ใน Hermes Desktop ไม่ได้มีแค่เลือกโมเดลถูกเท่านั้น แต่ต้องลดสิ่งที่ส่งเข้าโมเดลทุกครั้ง ได้แก่ tool schema, ประวัติแชต, project context, output ยาว ๆ, และการอ่านไฟล์/log แบบกว้างเกินไป

โมเดลถูกเป็นฐาน

ใช้ Gemini Flash หรือ DeepSeek Flash เป็น default สำหรับงานทั่วไป แล้วค่อยสลับไปโมเดลเก่ง/แพงเฉพาะงาน reasoning, coding หรือ debugging ที่จำเป็นจริง ๆ

แยก Profile ตามงบและประเภทงาน

Profile เดียวเปิดทุกอย่างจะสะดวกแต่เปลือง token เพราะต้องแบก tools/context หลายชุด แนะนำแยกเป็น profile เฉพาะทาง เพื่อให้แต่ละงานใช้โมเดลและ tools เท่าที่จำเป็น

Daily / Cheap

สำหรับคุยทั่วไป แปลภาษา brainstorm เขียนข้อความ สรุปสั้น ๆ

  • Model: Gemini Flash หรือ DeepSeek Flash
  • Tools: safe/minimal
  • Output: สั้น กระชับ
  • Reset เมื่อเปลี่ยนเรื่อง

Coding Budget

สำหรับแก้โค้ดแบบประหยัด ไม่เปิดเครื่องมือเกินจำเป็น

  • Model: DeepSeek Flash / coding model
  • Tools: file + terminal + skills
  • ปิด browser/image/video ถ้าไม่ได้ใช้
  • อ่านเฉพาะไฟล์ที่เกี่ยวกับ error

Research / Browser

สำหรับค้นเว็บ อ่านบทความ ใช้ browser automation เฉพาะงานนั้น

  • เปิด web/browser เฉพาะ profile นี้
  • ค้นทีละคำถาม
  • สรุปเป็น notes สั้น ๆ
  • จบงานแล้ว reset
หลักคิด: daily profile ควรเบาที่สุด ส่วน coding/research ค่อยเปิดความสามารถเพิ่มเฉพาะตอนต้องใช้จริง

Toolsets: ตัวกิน Token ที่มักมองไม่เห็น

Tools ช่วยให้ Hermes ลงมือทำได้ แต่แต่ละ tool มี schema ที่ต้องส่งให้โมเดลเข้าใจ ถ้าเปิดเยอะเกินไปจะเพิ่ม input token ทุกครั้ง ควรจัดเป็นชุดตามงาน

งานเปิด Toolsปิด/เลี่ยงเหตุผล
คุยทั่วไปsafe/minimalbrowser, terminal, file, image, videoไม่ต้องลงมือทำ จึงไม่ควรแบก schema หนัก
เขียนโค้ดfile, terminal, skillsbrowser, video, image_gen, computer_useพอสำหรับอ่าน/แก้/ทดสอบโค้ด
ค้นเว็บweb/search หรือ browserimage/video ถ้าไม่ได้ใช้เปิดเฉพาะ session ที่ต้องค้นจริง
งานเอกสารfile, skills เฉพาะ doc/pdf/xlsxtools ทั่วไปที่ไม่เกี่ยวลด schema และลดการเรียกใช้ผิดทาง

คำสั่งแนวทาง

hermes tools hermes tools disable browser hermes tools disable image_gen hermes tools disable video_gen hermes tools disable x_search hermes tools disable computer_use

หลังเปลี่ยน tools ให้เริ่ม session ใหม่หรือ /reset เพื่อให้ผลมีผลกับ context รอบใหม่

ข้อควรจำ

  • ปิด tools ไม่ได้แปลว่าใช้งาน Hermes แย่ลง ถ้างานนั้นไม่ต้องใช้
  • เปิด tools เฉพาะเวลาจำเป็น แล้ว reset หลังจบงาน
  • อย่าใช้ profile เดียวเปิดครบทุก tool ถ้าเป้าคือประหยัด token

Context Management: จุดประหยัด Token ที่เห็นผลมาก

Context คือทุกอย่างที่โมเดลเห็น: ประวัติแชต, ไฟล์ที่อ่าน, log, project rules, memory และคำตอบเก่า ยิ่ง context โต ค่า token ยิ่งสูง

ใช้ targeted readingอย่าสั่ง “ดู repo ทั้งหมด” ถ้ายังไม่จำเป็น ให้เริ่มจาก error, stack trace, หรือไฟล์ที่เกี่ยวข้องก่อน
ทำ summary checkpointงานยาวให้สรุป context ที่จำเป็น แล้วเปิด session ใหม่ด้วย summary แทนประวัติยาวทั้งหมด
คุม project rulesAGENTS.md / .hermes.md / CLAUDE.md ควรสั้น เน้น convention สำคัญ ไม่ควรใส่ spec หรือ README ยาว ๆ
ลด raw logsให้ดู log เฉพาะช่วงล่าสุดหรือเฉพาะ error ใหม่ แทนการ dump output ทั้งหมด

Prompt แบบเปลือง

ช่วยดู repo นี้ทั้งหมดว่ามีปัญหาอะไร

Prompt แบบประหยัด

วิเคราะห์จาก error นี้ก่อน อ่านเฉพาะไฟล์ที่เกี่ยวข้อง ถ้าต้องอ่านไฟล์เกิน 3 ไฟล์ ให้ถามก่อน

Workflow ที่แนะนำสำหรับงานแต่ละแบบ

เลือก workflow ให้ตรงงาน จะช่วยลดการวนถาม-ตอบ ลด context และลดการใช้โมเดลแพงโดยไม่จำเป็น

Daily Chat

  1. เริ่มด้วย Gemini Flash
  2. ตอบสั้นไม่เกิน 5 bullet
  3. ไม่เปิด tools หนัก
  4. /reset เมื่อเปลี่ยนเรื่อง

Debug / Coding

  1. ส่ง error/stack trace ก่อน
  2. ให้ agent ระบุไฟล์ที่ต้องอ่าน
  3. อ่านเฉพาะไฟล์จำเป็น
  4. run test เฉพาะส่วนที่เกี่ยว
  5. สรุป progress แล้ว reset หากยาว

Research

  1. เปิด web/browser เฉพาะ session
  2. ถามทีละประเด็น
  3. สรุปเป็น notes สั้น
  4. เก็บเฉพาะข้อสรุป ไม่เก็บ raw ทั้งหมด
แนวทางสำคัญ: ให้โมเดลถูกทำงานแรกก่อน ถ้าผลไม่พอค่อย switch โมเดลแพง ไม่ควรเริ่มทุกงานด้วยโมเดลแพง

Configuration ที่ช่วยคุม Token

การตั้งค่าที่เกี่ยวข้องมากที่สุดคือ model, tools, compression, display/reasoning, และ project context โดยควรปรับผ่านคำสั่ง Hermes ไม่ hand-edit config ถ้าไม่จำเป็น

Compression

ช่วยย่อ context เมื่อบทสนทนายาว ควรเปิดไว้สำหรับคนต้องการประหยัด token

hermes config set compression.enabled true

Reasoning / Output

งานทั่วไปไม่จำเป็นต้อง reasoning หนักหรือโชว์รายละเอียดมาก ให้ใช้ reasoning ต่ำ/none ถ้าระบบและ provider รองรับ

งานทั่วไป: reasoning ต่ำ/none งานยาก: ค่อยเปิด reasoning มากขึ้น

Fallback Chain

ใช้โมเดลถูกก่อน แพงทีหลัง เช่น Gemini Flash → DeepSeek ตัวเก่งขึ้น → GPT/Claude เฉพาะงานยาก

Project Instructions

เขียน rules ให้สั้น เช่น package manager, test command, source directory, files ที่ห้ามแก้ อย่าใส่เอกสารยาว

- Use pnpm, not npm. - Run tests with pnpm test. - Source code is in src/. - Do not modify generated files.

Prompt Templates สำหรับประหยัด Token

Template prompt ช่วยลดการคุยวน บังคับ output ให้สั้น และป้องกัน agent อ่านข้อมูลเกินจำเป็น

สรุปข้อความ

สรุปเป็น 5 bullet: - ประเด็นหลัก - สิ่งที่ต้องทำ - deadline ถ้ามี ไม่ต้องเล่าซ้ำทุกประโยค

Debug

วิเคราะห์จาก error นี้ก่อน ห้ามอ่านทั้ง repo ถ้ายังไม่จำเป็น บอกไฟล์ที่ต้องการเพิ่มก่อน

Code Review

รีวิวเฉพาะ bug/security/regression ไม่ต้อง comment เรื่อง style เล็กน้อย ตอบเป็น priority P0/P1/P2

งานยาว / Checkpoint

ช่วยสรุป context ที่จำเป็นต่อการทำงานต่อให้สั้นที่สุด เอาเฉพาะไฟล์ที่แก้, decision, pending issue, command ที่ต้องรันต่อ

จำกัด Output

ตอบสั้น ไม่เกิน 5 bullet ไม่ต้องอธิบายพื้นฐาน ถ้าไม่มั่นใจให้ถามก่อน

ขออนุญาตก่อนอ่านเยอะ

ถ้าต้องอ่านไฟล์เกิน 3 ไฟล์ หรือใช้ context เยอะ ให้ถามก่อน อย่าโหลดข้อมูลจำนวนมากโดยไม่จำเป็น

Checklist สำหรับตั้งค่า Hermes Desktop แบบประหยัด

ใช้ checklist นี้ก่อนเริ่มใช้งานจริง โดยเฉพาะถ้าจะต่อกับ DeepSeek Flash / Gemini Flash และมีงบ token จำกัด

ก่อนเริ่ม

  • ตั้ง Gemini Flash / DeepSeek Flash เป็น default
  • เปิด compression
  • ปิด tools ที่ไม่ใช้
  • แยก profile daily/coding/research
  • ตรวจ project instruction ว่าไม่ยาวเกิน

ระหว่างใช้งาน

  • ถามให้แคบและเฉพาะเจาะจง
  • จำกัด output เป็น bullet
  • ไม่ dump log/file ทั้งหมด
  • ให้ถามก่อนอ่านไฟล์เยอะ
  • /reset เมื่อเปลี่ยนเรื่อง

เมื่อเจองานยาก

  • ให้โมเดลถูกลองก่อน
  • ถ้าติด reasoning ค่อย switch โมเดล
  • เปิด tools เพิ่มเฉพาะ session นั้น
  • หลังจบงาน สรุปแล้ว reset

สัญญาณว่าเริ่มเปลือง

  • session ยาวมาก
  • คำตอบเริ่มอ้าง context เก่าเยอะ
  • เปิด tools ครบทั้งที่ไม่ได้ใช้
  • project rule ยาวหลายหน้า
  • ชอบสั่ง “ดูทั้งหมด” ก่อนรู้จุดปัญหา
สรุปสุดท้าย: ถ้าอยากใช้ Hermes Desktop ให้คุ้ม ให้แยก profile, เปิด tools เท่าที่จำเป็น, คุม context, จำกัด output และใช้โมเดลถูกเป็นตัวหลักค่ะ
