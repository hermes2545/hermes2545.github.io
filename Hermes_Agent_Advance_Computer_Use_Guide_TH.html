3Best-effort background แปลว่าอะไร

Background ก่อน

พยายามส่ง action ถึง target โดยไม่เอาหน้าต่างขึ้นหน้า ไม่ย้ายเมาส์ และไม่ขโมย keyboard focus

ไม่ใช่ 100%

บางแอปหรือบาง surface รับ input เฉพาะ foreground จึงต้องดู verdict จาก driver ก่อนตัดสินใจ

Foreground เป็น fallback

ยกระดับเฉพาะ action ที่จำเป็น ไม่ควรตั้งสมมติฐานว่าแอปใด “ต้อง foreground” ตั้งแต่แรก

กรอบคิดที่ถูก: ภาพหน้าจอ + accessibility tree + action policy ทำงานร่วมกัน จึงไม่ใช่ระบบ “มองภาพแล้วคลิกพิกัด” อย่างเดียว

OS runbook

Prerequisite ไม่เหมือนกันในแต่ละ OS

macOS ติดที่ permission/TCC, Windows ติดที่ interactive session และ integrity boundary, Linux ติดที่ display server และความต่างของ X11 กับ Wayland

ต้องมีสิทธิ์ 2 อย่าง

  • Accessibility
  • Screen Recording

Grant ให้ identity ที่ hermes computer-use doctor ระบุ; standard mode มักเป็น CuaDriver.app

macOS permissions
hermes computer-use permissions status
hermes computer-use permissions grant
อย่าเปิดแอปแบบบังคับ foreground เช่นใช้ open -a ... หากโจทย์ต้องการ background control จริง เพราะขัดกับ no-foreground contract

จุดที่อาจ degraded

SwiftUI บาง surface, game/canvas, หรือหน้าต่างบน Space อื่น อาจอ่าน AX หรือ routed input ได้ไม่ครบ → ใช้ fallback หรือ foreground เฉพาะ action

1 · Session 0 ผ่าน SSH

OpenSSH บน Windows อาจอยู่ Session 0 ซึ่งไม่มี interactive desktop → list_windows ว่าง, screenshot/click ไม่เห็นหน้าต่างของ user

2 · Administrator windows

Hermes ที่รัน medium integrity คุมหน้าต่าง elevated ไม่ได้ตามปกติ เพราะ UIPI บล็อก input

3 · Native vs WSL2

ถ้าจะคุมแอป Windows จริง ให้ใช้ native Windows ตรงกว่า WSL2 เพราะ app/profile อยู่ฝั่ง Windows

Core workflow

Capture → Element Action → Verify → Read Verdict

นี่คือ workflow ที่ควรฝึกจนเป็นนิสัย: ดู state ปัจจุบันก่อน, เลือก element index แทน coordinate, verify หลัง mutation และอ่าน verdict ก่อนทำ action ถัดไป

Step 1Captureเริ่มด้วย mode="som"
Step 2Element firstคลิกด้วย index ก่อนพิกัด
Step 3Verifycapture ใหม่ / capture_after
Step 4Verdictconfirmed / unverifiable / noop

1Capture ก่อนเสมอ

Python-like tool call
computer_use(action="capture", mode="som", app="Chrome")

som

โหมดหลัก: screenshot + overlay หมายเลข element + accessibility tree index

vision

ภาพล้วน เหมาะเมื่อ overlay บังสิ่งที่ต้องดู

ax

tree อย่างเดียว เหมาะกับ text-only model หรืออยากลดการพึ่งภาพ

2Element index ก่อน coordinate

Preferred
computer_use(action="click", element=14)

ทำไมเสถียรกว่า

ลดโอกาสคลิกพลาด และ driver สามารถผูก action กับ accessibility path เพื่อช่วยยืนยันผลได้ดีกว่า

3Verify หลัง action

Capture after mutation
computer_use(action="click", element=14, capture_after=True)

4อ่าน verdict ก่อน retry

Verdict / Codeความหมายควรทำต่อ
effect: confirmeddriver ยืนยันผลได้แล้วทำ step ถัดไป
effect: unverifiableส่ง input แล้ว แต่ผลยังยืนยันไม่ได้capture/check state ใหม่ก่อนสรุป
effect: suspected_noopน่าจะไม่เกิดผลดู recommendation; อาจไป pixel
background_unavailablebackground path ใช้กับ action/target นี้ไม่ได้พิจารณา rung ที่ driver แนะนำ
สิ่งที่ไม่ควรทำ: คลิกซ้ำ ๆ โดยไม่ capture ใหม่ เพราะ element index ผูกกับ snapshot ล่าสุดและอาจ stale ได้

อย่าเดา — ไต่ระดับตามสัญญาณจาก driver

2ถ้า unverifiable

Capture ใหม่ก่อน ดู state ล่าสุดและอย่า retry action เดิมอัตโนมัติ เพราะ input อาจถูกส่งไปแล้วแต่ยังยืนยันไม่ได้

4ถ้า driver แนะนำ “page”

ใช้ typed browser rung ก่อน foreground

เมื่อ target เป็น browser page content และ binding exact พิสูจน์ได้ ให้ใช้ action ตระกูล cua_browser_* เพื่อทำ mutation กับ semantic page ref ที่ผูกกับ DOM/page state โดยตรง

5Foreground เฉพาะ action

Last resort for that action
computer_use(action="click", element=7, delivery_mode="foreground")
Cheat sheet: confirmed → ไปต่อ · unverifiable → capture ใหม่ · suspected_noop → พิจารณา px · page → typed browser · background unavailable → foreground เฉพาะเมื่อจำเป็น
06 / 13
Browser bridge

Browser จริง, Typed Page Rung และ Profile ที่ล็อกอินอยู่

Computer Use ใช้ browser จริงของผู้ใช้ได้ แต่ต้องแยกให้ชัดระหว่าง page content กับ browser chrome / native dialog และ existing profile ต้อง opt-in แบบ explicit

1เลือกเครื่องมือให้ถูก

เว็บล้วน + ไม่ต้องใช้ profile จริง

เริ่มด้วย browser_* เพราะเสถียรกว่าและไม่ชนข้อจำกัด desktop OS

ต้องใช้ browser ที่เปิดจริง

ใช้ computer_use เพื่อเข้าถึงหน้าต่าง/profile ที่ผู้ใช้ใช้อยู่

Page content ที่ driver แนะนำ

สลับไป typed cua_browser_* เพื่อใช้ semantic page refs

2Typed browser rung — ขั้นตอนที่ต้องแม่น

  1. bind browser state ด้วย (pid, window_id) ให้ได้ exact
  2. ตรวจ binding_quality="exact" และ mutation_allowed=true
  3. เอา tab_id
  4. ขอ snapshot ใหม่
  5. ใช้ ref ล่าสุดเท่านั้น
  6. หลังทุก mutation ต้อง refresh state ใหม่
ยังต้องใช้ native path สำหรับ browser chrome, permission UI, native dialog และ OS prompt

3Existing profile ที่ล็อกอินอยู่

Explicit opt-in
hermes config set computer_use.grant_existing_profile true
Conceptual YAML
computer_use:
  grant_existing_profile: true
Default = fail closed. การเปิด YOLO ไม่ได้แทน explicit existing-profile grant เพราะ profile จริงอาจเปิดทางเข้าถึง cookie / storage / live pages ได้
07 / 13
Security boundary

Standard · Bounded · Unrestricted

เลือก permission mode ตามระดับความเสี่ยงและความอัตโนมัติ ไม่ใช่ตามความสะดวกอย่างเดียว โดย bounded เหมาะกับงาน unattended ที่ต้องการขอบเขตชัดที่สุด

Recommended start

standard

งานทั่วไป อนุญาต routine action ส่วนใหญ่ แต่ boundary สำคัญยังต้อง grant ตอน launch

Automation

bounded

เหมาะกับ cron / unattended / recurring automation ต้องมี capability manifest และนอก scope จะ fail closed

High risk

unrestricted

สำหรับ sandbox/VM/disposable environment ที่ยอมรับความเสี่ยงเต็ม หลัง acknowledge ความเสี่ยง

1ตั้งค่า bounded mode

Hermes CLI
hermes config set computer_use.permission_mode bounded
hermes config set computer_use.capability_manifest ~/.hermes/cua-manifest.yaml
Conceptual YAML
computer_use:
  permission_mode: bounded
  capability_manifest: ~/.hermes/cua-manifest.yaml

2Baseline สำหรับผู้ใช้ทั่วไป

Standard + existing profile off
hermes config set computer_use.permission_mode standard
hermes config set computer_use.grant_existing_profile false
Unrestricted ไม่ได้ป้องกัน prompt injection หรือ unintended model actions. ใช้กับเครื่องหลักหรือ browser profile สำคัญก็ต่อเมื่อยอมรับความเสี่ยงนั้นจริง ๆ
