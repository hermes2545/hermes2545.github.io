ระบบนี้คืออะไร

ระบบนี้คือการนำ Hermes Agent มาตั้งค่าให้เป็นผู้ช่วย AI ที่เชื่อมต่อกับบัญชี Google และช่องทางสื่อสารของทีมได้อย่างเป็นระบบ โดย Hermes ไม่ได้เป็นแค่แชตบอตตอบคำถาม แต่เป็น “ตัวปฏิบัติงาน” ที่สามารถ:

  • อ่านและจัดการข้อมูลจาก Google Workspace
  • สร้าง/แก้ไข/จัดเก็บเอกสารใน Google Drive
  • จัดการ Gmail, Calendar, Sheets, Docs และไฟล์นำเสนอผ่าน Google Drive หรือ Slides API
  • รับคำสั่งจาก Google Chat และ LINE
  • ตอบกลับในห้องหรือเธรดเดิมอย่างมีบริบท
  • เก็บความรู้และขั้นตอนการทำงานไว้ใช้ซ้ำผ่าน memory, skills, session history และ wiki
  • ทำงานอัตโนมัติแบบตั้งเวลาได้ผ่าน cron jobs
  • แยกงานส่วนตัว งานทีม และงานสาธารณะออกจากกันอย่างปลอดภัย

แนวคิดหลักคือทำให้ Hermes กลายเป็น AI Operations Layer ที่อยู่ตรงกลางระหว่างผู้ใช้, ทีมงาน, Google Workspace, ระบบเอกสาร, ระบบความจำ และช่องทางสื่อสารต่าง ๆ

บัญชี Google แบบ Dedicated Account

ระบบนี้ควรมี Google Account เฉพาะสำหรับ Hermes 1 บัญชี เช่น:

code
<GOOGLE_ACCOUNT_EMAIL>

ไม่ควรใช้บัญชีส่วนตัวหลักของมนุษย์เป็นบัญชีระบบโดยตรง เพราะบัญชีเฉพาะช่วยให้:

  1. แยกสิทธิ์ของ AI ออกจากบัญชีส่วนตัว
  2. ตรวจสอบประวัติการส่งอีเมล/สร้างไฟล์/แก้เอกสารได้ชัดเจน
  3. แชร์โฟลเดอร์และไฟล์ให้ทีมได้โดยไม่ปะปนกับข้อมูลส่วนตัว
  4. ย้ายเครื่องหรือติดตั้งระบบใหม่ได้ง่าย
  5. ปิด/หมุน/จำกัดสิทธิ์ของ AI ได้โดยไม่กระทบบัญชีคนจริง
  6. เหมาะกับการทำ automation ระยะยาว

บัญชีนี้ควรเปิด 2-Step Verification และเก็บ recovery method ไว้อย่างปลอดภัย

หมวด 5

Google Workspace ทำอะไรได้บ้าง

5.1 Gmail

Hermes สามารถ:

  • ค้นหาอีเมลด้วย Gmail search syntax
  • อ่านอีเมลและ thread
  • ส่งอีเมลใหม่
  • ตอบกลับใน thread เดิม
  • เพิ่ม/ลบ label
  • mark read/unread
  • archive หรือจัดการสถานะอีเมล

ควรมีนโยบายความปลอดภัยว่า การส่งอีเมลจริงต้อง preview และขออนุมัติก่อน ยกเว้น workflow ที่เจ้าของระบบตั้ง policy ไว้ชัดเจนแล้ว

5.2 Google Drive

Hermes สามารถ:

  • ค้นหาไฟล์
  • สร้างโฟลเดอร์
  • อัปโหลดไฟล์
  • ดาวน์โหลดไฟล์
  • ดู metadata
  • แชร์ไฟล์
  • ย้ายไฟล์ด้วย pattern download/upload/delete เมื่อเครื่องมือไม่มีคำสั่ง move โดยตรง
  • เก็บ OUTBOX สำหรับไฟล์ส่งมอบ
  • เก็บ INBOX สำหรับไฟล์ที่ผู้ใช้ส่งให้ AI ประมวลผล

Drive เป็นศูนย์กลางสำหรับไฟล์ที่มนุษย์ต้องเปิดดู แชร์ หรือส่งต่อ

5.3 Calendar

Hermes สามารถ:

  • อ่านตารางนัดหมาย
  • สร้าง event
  • ลบ event
  • ใส่สถานที่ รายละเอียด และผู้เข้าร่วม

ทุก event ต้องใช้วันเวลาแบบมี timezone เช่น:

code
2026-01-01T10:00:00+07:00

5.4 Sheets

Hermes สามารถ:

  • สร้าง spreadsheet
  • อ่าน range
  • update range
  • append row
  • ใช้เป็น log, tracker, report หรือ lightweight database

เหมาะกับงานที่ต้องมีตาราง ตรวจสอบย้อนหลัง และให้คนอื่นเปิดดูง่าย

5.5 Docs

Hermes สามารถ:

  • สร้าง Google Docs
  • อ่านเนื้อหา Docs
  • append ข้อความ
  • ทำเอกสารจาก Markdown/HTML
  • ใช้ template แล้วสร้างสำเนาก่อนแก้

หลักสำคัญคือ ห้ามแก้ template ต้นฉบับโดยตรง ให้ copy/import เป็นเอกสารใหม่ก่อนเสมอ

5.6 Slides

Slides ใช้ได้ 2 ระดับ:

  1. Drive-level mode — จัดเก็บ แชร์ ดาวน์โหลด/ส่งออกไฟล์นำเสนอ เช่น PPTX/PDF ผ่าน Drive
  2. Slides API mode — สร้างหรือแก้ slide แบบ programmatic โดยเพิ่ม Google Slides API และ scope presentations

หากต้องใช้ presentation จริงจัง ควรมี helper script เฉพาะสำหรับสร้าง/แก้ slide และ export เป็น PDF เพื่อตรวจ layout

หมวด 7

Google Chat สำหรับทีมและแผนก

Google Chat เหมาะกับห้องทำงานแบบทีม เช่น:

  • ห้องรวมของทีม
  • ห้องของแต่ละแผนก
  • ห้องแจ้งเตือนระบบ
  • DM กับผู้ใช้เฉพาะคน
  • thread สำหรับแต่ละประเด็น

7.1 โครงสร้างการเชื่อมต่อ

code
Google Chat Space / DM
  → Google Chat App
  → Cloud Pub/Sub Topic
  → Pub/Sub Subscription
  → Hermes Gateway
  → Hermes Agent
  → reply กลับไปยัง space/thread เดิม

สำหรับระบบโต้ตอบสองทาง ควรใช้ Google Chat App + Pub/Sub ไม่ใช่ incoming webhook อย่างเดียว เพราะ webhook เหมาะกับการส่งแจ้งเตือนขาออกแบบทางเดียวมากกว่า

7.2 นโยบายสำหรับห้องทีม

ควรกำหนด policy ต่อห้อง เช่น:

yaml
google_chat_spaces:
  - name: "<DEPARTMENT_NAME>"
    space_id: "spaces/<SPACE_ID>"
    purpose: "<PURPOSE>"
    response_policy: "mention_only"
    escalation_channel: "<PRIVATE_OPERATOR_CHANNEL>"

แนวทาง:

  • ถ้าเป็น shared room ให้ตอบเมื่อมีการ mention หรือเรียก Hermes ชัดเจนเท่านั้น
  • ตอบใน thread เดิมเมื่อคำถามอยู่ใน thread
  • คำตอบในห้องทีมควรกระชับ
  • ถ้าเกี่ยวกับ credential, permission, policy หรือข้อมูล sensitive ให้หยุดและ escalate ไป private operator channel
  • ห้ามเผยแพร่ memory ส่วนตัวหรือ config ลับในห้องทีม

หมวด 8

LINE สำหรับกลุ่มงานและทีมภาคสนาม

LINE เหมาะกับทีมที่ทำงานบนมือถือหรือคุ้นกับ LINE group มากกว่า Google Chat

8.1 โครงสร้างการเชื่อมต่อ

code
LINE Group / LINE DM
  → LINE Official Account
  → Messaging API Webhook
  → HTTPS endpoint
  → Hermes Gateway LINE adapter
  → Hermes Agent
  → reply/push กลับไปยัง LINE

8.2 LINE Official Account

ต้องมี:

  • LINE Official Account สำหรับ Hermes
  • Messaging API เปิดใช้งาน
  • Channel secret
  • Channel access token
  • Webhook URL แบบ HTTPS
  • allowlist ของ user/group ที่อนุญาต

8.3 นโยบายเงียบใน group

LINE group มักมีบทสนทนาจำนวนมาก จึงควรตั้ง rule ชัดเจน:

  • LINE_ALLOWED_GROUPS หมายถึงกลุ่มนี้ได้รับอนุญาต ไม่ได้แปลว่าทุกข้อความคือคำสั่ง
  • Hermes ควรตอบเฉพาะเมื่อมี trigger เช่น Hermes, /hermes หรือคำเรียกที่กำหนด
  • ข้อความทั่วไป ประกาศ หรือการคุยกันเองควรถูก ignore
  • ถ้ามีงาน sensitive ให้ย้ายไป private operator channel

8.4 แผนก/ทีมใน LINE

ควรเก็บ mapping แบบ private เช่น:

yaml
line_workgroups:
  - department: "<DEPARTMENT_A>"

## 1. Design Goals

### 1.1 Functional goals

The target Hermes system must be able to:

- Search, read, send, reply to, label, archive, and manage Gmail messages.
- Read and create Google Calendar events with timezone-correct timestamps.
- Search, upload, download, create folders, share, and trash/delete files in Google Drive.
- Create, read, update, and append data in Google Sheets.
- Create, read, and append Google Docs.
- Handle Google Slides through either:
  - Drive-level storage/export/share operations; and/or
  - an optional Slides API helper when programmatic slide creation/editing is required.
- Receive requests from Google Chat spaces or DMs and reply to the same space/thread.
- Receive requests from LINE groups/DMs and reply only when explicitly triggered.
- Keep durable knowledge in a local wiki and optionally mirror public/sanitized outputs to Drive.
- Use reusable skills/procedures so repeated tasks improve over time.
- Run scheduled jobs with clear logging, safe delivery, and no hidden failures.

### 1.2 Non-functional goals

The system must be:

- **Safe:** no uncontrolled public sharing, accidental email sends, or group-chat noise.
- **Auditable:** important actions have local logs, Drive outputs, or session history.
- **Recoverable:** configuration, OAuth, and folder IDs are documented in a local setup note.
- **Portable:** all private values use placeholders in public docs.
- **Least privilege where practical:** scopes and platforms are enabled intentionally.
- **Human-governed:** the owner keeps final authority over sensitive sends, deletions, sharing, and credential changes.

## 2. Required Dedicated Google Account

### 2.1 Why a dedicated Google account is mandatory

Use **one dedicated Google account** for the Hermes integration. Do not use a human’s primary personal account as the automation identity unless there is no alternative.

Recommended placeholder:

```text
<GOOGLE_ACCOUNT_EMAIL> = hermes-assistant@example.com
```

Reasons:

1. **Clean permission boundary** — all files, emails, calendars, Chat app ownership, and API activity are attributable to the assistant account.
2. **Reduced privacy risk** — the assistant does not automatically inherit a human’s entire personal mailbox/Drive unless explicitly delegated.
3. **Simpler recovery** — if the machine is replaced, reauthorizing the assistant account restores the system surface.
4. **Operational continuity** — team workflows do not break when a human changes roles, loses access, or rotates devices.
5. **Safer sharing model** — Drive folders and Google Chat rooms can add the assistant account/app intentionally.
6. **Easier auditing** — Gmail sent mail, Drive ownership, Calendar events, and Chat messages are separated from personal human actions.

### 2.2 Account setup policy

For the dedicated account:

- Enable 2-Step Verification.
- Store recovery email/phone in the organization’s password manager or secure admin vault.
- Use a strong unique password.
- Keep OAuth client credentials separate from the Google account password.
- Do not paste password, backup codes, OAuth client secret, service-account key, refresh token, or LINE token into chats.
- If using a Google Workspace domain, confirm admin policies allow:
  - external/internal OAuth app testing as needed;
  - Google Chat app visibility;
  - Pub/Sub connection for Google Chat apps;

## 19. Cron and Automation Design

### 19.1 Cron principles

Hermes cron jobs run as fresh unattended sessions. Design them so they do not require live user approval.

A good cron job has:

- self-contained prompt;
- explicit schedule;
- fixed scripts for mechanical work;
- safe delivery target;
- no secrets in prompt;
- no destructive actions unless narrowly scoped;
- clear silent/no-op behavior;
- clear error reporting.

### 19.2 Delivery channels

| Delivery target | Use for |
|---|---|
| private operator chat | sensitive or technical status |
| email | formal reports, durable summaries |
| Google Chat | team-visible operational updates |
| LINE | short reminders/updates, quota permitting |
| local only | logs, ingestion, maintenance |

### 19.3 No-op behavior

For recurring monitors:

- Stay silent when nothing changed.
- Send a message only when there is action, error, or blocker.
- For script-only watchdogs, empty stdout should mean no delivery.

### 19.4 Cron safety

- Do not let cron jobs recursively create more cron jobs.
- Avoid ad-hoc heredoc scripts in unattended cron contexts.
- Prefer stable helper scripts under `<HERMES_HOME>/scripts/`.
- Log enough to debug without exposing secrets.
- Use Drive OUTBOX or email for user-visible reports when appropriate.

## 22. Troubleshooting Matrix

| Problem | Likely cause | Fix |
|---|---|---|
| Google OAuth `access_denied` | account not test user or app policy | add account as test user / adjust audience |
| `NOT_AUTHENTICATED` | token missing | redo OAuth flow |
| `REFRESH_FAILED` | token revoked/expired | revoke and reauthorize |
| `Insufficient Permission` | missing scope | add scope, revoke, reauthorize |
| Drive upload creates duplicates | no exact pre-search | search by name and parent before upload |
| Gmail send blocked | missing approval or recipient guard | show preview and approve |
| Calendar times wrong | timezone omitted | use ISO 8601 with offset |
| Google Chat outbound works but inbound fails | Pub/Sub publisher IAM/config | grant publisher, save config, re-add app |
| Google Chat cannot post | app not in space | add app to space |
| LINE webhook verify fails | public URL inaccessible/signature issue | verify HTTPS endpoint and channel secret |
| LINE group ignored | group/user not allowed or trigger missing | add IDs/restart or use explicit trigger |
| LINE scheduled messages fail | quota exhausted | monitor quota or route fallback |
| Hermes config change not active | gateway/session not restarted | restart gateway or start new session |
