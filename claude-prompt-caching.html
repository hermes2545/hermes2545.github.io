Overview

เข้าใจ Prompt Caching ในไม่กี่นาที

แทนที่จะให้ AI อ่านข้อมูลเดิมใหม่ทุกครั้ง ระบบสามารถจำส่วนเดิมไว้และใช้ซ้ำ ทำให้ต้นทุนของส่วนที่ cache ได้ลดลงอย่างมาก

ไม่ต้องมีพื้นฐานโค้ด
ความลับของ AI ที่ทำให้จ่าย แค่เศษเดียว

ลองนึกถึงร้านกาแฟ: ลูกค้าประจำสั่งเมนูเดิมทุกเช้า ถ้าเตรียมส่วนเดิมไว้แล้ว ก็ไม่จำเป็นต้องเริ่มใหม่ทั้งหมดทุกครั้ง — นี่คือแนวคิดของ Prompt Caching

🧱 Context Order

วางของที่ “ไม่เปลี่ยน” ไว้ก่อน ของที่เปลี่ยนบ่อยไว้ท้าย

Cache ใช้ต่อได้เมื่อ prefix เดิมตรงกัน ดังนั้นสิ่งคงที่ควรอยู่ด้านบนและสิ่ง dynamic ควรอยู่ด้านล่าง

Static → Dynamic
คำสั่งตั้งต้น + เครื่องมือ“นายเป็นใคร ทำงานยังไง” — ไม่ควรเปลี่ยนบ่อย
GLOBAL
กฎของโปรเจกต์ (CLAUDE.md)กติกาเฉพาะงานนี้
PROJECT
ข้อมูลของรอบงานนี้บริบทเฉพาะ session
SESSION
บทสนทนาที่กำลังคุยกันเปลี่ยนทุกข้อความ จึงมีส่วนใหม่ให้ AI อ่าน
DYNAMIC
หลักจำง่ายที่สุด

📋 Seven Rules

กฎทอง 7 ข้อ — เลือกอ่านทีละข้อ

แทนการวาง accordion ยาวลงมา กดหมายเลขเพื่อเปลี่ยนเนื้อหาใน card เดิม

Compact selector
1. วางของที่ไม่เปลี่ยนไว้ก่อน ของที่เปลี่ยนไว้ทีหลัง

เรียงข้อมูลให้ส่วนที่ “เหมือนเดิมทุกครั้ง” อยู่ข้างบน ส่วนที่ “เปลี่ยนบ่อย” อยู่ข้างล่าง

☕ เปรียบเหมือน
จัดตู้เย็น — ของแห้งที่อยู่ได้นานไว้ชั้นบน ของสดที่ใช้แล้วหมดไว้ชั้นล่าง หยิบง่ายไม่ต้องรื้อทั้งตู้
⚠ ระวัง
อย่าใส่ “เวลาปัจจุบัน” ที่เปลี่ยนทุกวินาทีไว้ในคำสั่งตั้งต้น เพราะอาจทำให้ prefix เปลี่ยนทุกครั้ง
2. มีอะไรใหม่ ให้ส่งข้อความบอก อย่าแก้คำสั่งตั้งต้น

อยากอัปเดตข้อมูล เช่น เวลาตอนนี้หรือไฟล์ที่เพิ่งแก้ ให้พิมพ์บอกในข้อความถัดไปแทนการเปลี่ยน system prompt

☕ เปรียบเหมือน
แทนที่จะพิมพ์เมนูร้านใหม่ทั้งแผ่นเพราะราคาเปลี่ยนเล็กน้อย แค่ติดป้ายอัปเดตเพิ่มก็พอ
✓ ผลลัพธ์
คำสั่งตั้งต้นยังเหมือนเดิม → cache ส่วนเดิมยังมีโอกาสใช้ต่อได้
3. อย่าสลับ “รุ่น AI” กลางคัน

ความจำ cache ของแต่ละ model แยกกัน การสลับรุ่นระหว่าง session อาจทำให้ต้องสร้าง cache ใหม่

☕ เปรียบเหมือน
เล่าเรื่องให้เพื่อนคนหนึ่งฟังมานาน แล้วเปลี่ยนไปคุยกับอีกคนที่ไม่รู้บริบท — ต้องเล่าใหม่อีกครั้ง
✓ ทางออก
ถ้าจำเป็นต้องใช้คนละรุ่น ให้แยกไปทำงานใน subagent แทนการเปลี่ยน model ของบทสนทนาหลัก
4. อย่าเพิ่ม-ลด “เครื่องมือ” กลางคัน

รายการ tool เป็นส่วนหนึ่งของข้อมูลที่โมเดลเห็น ถ้าชุดเครื่องมือเปลี่ยน prefix ก็เปลี่ยนตาม

☕ เปรียบเหมือน
กล่องเครื่องมือช่างที่จัดเหมือนเดิมทุกวัน ย่อมหยิบใช้ต่อเนื่องกว่ากล่องที่เปลี่ยนของเข้าออกตลอด
✓ ทางออก
เก็บชุดเครื่องมือให้คงที่ แล้วควบคุมพฤติกรรมด้วย mode หรือโหลดรายละเอียดเท่าที่จำเป็น
5. อยากเปลี่ยน “โหมด” ให้ใช้สวิตช์ ไม่ใช่ถอดเครื่องมือ

เช่น Plan mode ที่ให้ดูได้แต่ห้ามแก้ไฟล์ ควรเปลี่ยนสถานะด้วยคำสั่งหรือสวิตช์ โดยไม่แก้ชุด tools

☕ เปรียบเหมือน
รถยนต์มีโหมดประหยัด — กดปุ่มเปลี่ยนโหมด ไม่ใช่ถอดเครื่องยนต์ออก
✓ หลักการ
เปลี่ยน behavior โดยรักษาโครงสร้าง prompt/tool schema ให้คงที่เท่าที่ทำได้
6. มีเครื่องมือเยอะ ให้ “ซ่อนรายละเอียด” ไว้ก่อน

ถ้ามี tools จำนวนมาก ไม่จำเป็นต้องส่งรายละเอียดทั้งหมดทุกครั้ง ส่งรายชื่อก่อนแล้วค่อยโหลดรายละเอียดเฉพาะตัวที่ต้องใช้

☕ เปรียบเหมือน
เมนูร้านอาหารโชว์ชื่อเมนูก่อน ลูกค้าสนใจจานไหนค่อยเปิดรายละเอียดของจานนั้น
✓ ผลลัพธ์
รายการหลักคงที่กว่า และลด context ที่ไม่จำเป็นในแต่ละรอบ
7. คุยยาวเกินไป ให้ “ย่อความ” ต่อจากของเดิม

เมื่อ context ยาวมากจนต้อง compaction ให้สรุปต่อจากของเดิมโดยรักษาส่วนก่อนหน้าให้สอดคล้อง แทนการเปิด session ใหม่แบบตัดขาด

☕ เปรียบเหมือน
ประชุม 3 ชั่วโมงแล้วเขียนสรุปต่อท้ายบันทึกเดิม ไม่ใช่เรียกทุกคนกลับมาเล่าใหม่ตั้งแต่ต้น
✓ หลักการ
งานแยกย่อยหรือการย่อความควรอ้างอิงของเดิมให้ตรง เพื่อให้ continuity ดีที่สุด

📖 Glossary ฉบับเร็ว

Prompt (พรอมต์)
ทุกอย่างที่เราส่งให้ AI อ่าน = คำสั่ง + ข้อมูล + บทสนทนา
Token (โทเคน)
หน่วยนับข้อความ ยิ่งมากก็ยิ่งมี input ให้ประมวลผลมาก
Caching (แคชชิ่ง)
การจำส่วนที่เคยประมวลผลแล้วเพื่อนำกลับมาใช้ซ้ำ
Cache hit / miss
Hit = ส่วนเดิมตรงและใช้ cache ได้ • Miss = ต้องอ่านหรือสร้าง cache ใหม่
System prompt
คำสั่งตั้งต้นที่บอก AI ว่าเป็นใคร มีบทบาทและกฎการทำงานอย่างไร
Session
การคุยต่อเนื่องกันหนึ่งรอบ ตั้งแต่เริ่มจนจบ
Agent
AI ที่ทำงานเองได้หลายขั้นตอน เช่น Claude Code
เรียบเรียงเพื่ออธิบายให้เข้าใจง่าย จาก “Lessons from Building Claude Code: Prompt Caching Is Everything” โดย Thariq Shihipar (Anthropic)
