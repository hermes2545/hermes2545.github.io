สิ่งที่คลิปสอน

1. Live voice ไม่ใช่ TTS

TTS พูดได้แต่ฟังเราไม่ได้ ส่วน Live API ฟังและพูดแบบสดทั้งสองทาง

2. สถาปัตยกรรมมี 3 ส่วน

browser, Gemini Live และ backend ขนาดเล็กที่ถือ connection แล้วส่งผ่าน audio

3. Agent รู้สึกมีชีวิต

ระบบจับ tone, pauses, energy, วิธีพูด, stream response และ barge-in ได้ใกล้เคียงการคุยจริง

หลัก UX สำคัญ: การ interrupt ให้ไวควรหยุดเสียงฝั่ง client/local ทันทีเมื่อไมค์จับว่าผู้ใช้เริ่มพูด ไม่ควรรอสัญญาณเดินทางข้าม network ก่อน
hubArchitecture

สถาปัตยกรรมและ session

Browser

รับ mic/camera จากผู้ใช้ เล่นเสียงตอบกลับ แสดง transcription และหยุด playback เมื่อเกิด barge-in

Backend ขนาดเล็ก

ถือ WebSocket session, relay audio, รับ event, map function call ไปยัง action ภายในระบบ และส่ง tool response กลับ

Gemini Live

โมเดลประมวลผล multimodal stream แบบ low-latency พร้อม response modalities เช่น AUDIO

Stateful WebSocket

ต่างจาก request/response เพราะ connection ค้างไว้ ทำให้ส่งและรับ stream ต่อเนื่องใน session เดียว

sync_altCore loop

Loop หลัก: open → send → receive → play

แกนคิดของเดโมคือเปิด session แล้วส่ง/รับ stream อย่างต่อเนื่อง ไม่ใช่เรียก API เป็นก้อนเดียวแล้วจบ

conceptual loop
open live session
while connected:
    send_realtime_input(mic_audio)
    async for event in session.receive():
        if event.audio:
            play(event.audio)
        if event.tool_call:
            result = run_tool_fast(event.tool_call)
            send_tool_response(result)
constructionTool use

ทำ agent ที่ “ลงมือทำ” ได้

Function declarations

ประกาศ schema ของ action ที่โมเดลเรียกได้ เพื่อให้คำพูดใน conversation กลายเป็นคำสั่งระบบที่ตรวจสอบได้

Fast handler

function call ใน live session เป็น synchronous ในเชิงประสบการณ์เสียง ถ้า tool ช้า agent จะเงียบระหว่างรอ จึงควร return ให้ไว

External worker

งานยาวควรส่งต่อให้ระบบอื่นจัดการ แล้วให้ voice agent แจ้งสถานะหรือผลลัพธ์เมื่อพร้อม แทนการ block session

warningImplementation cautions

ข้อควรระวังจากเดโม

1. session.receive() เป็น per-turn async generator

ถ้าอ่านแค่ครั้งเดียว agent อาจตอบได้หนึ่งช่วงแล้วเงียบ ต้องมี while True หรือ loop ต่อเนื่องครอบการรับ event เพื่อให้สนทนาทั้ง session ไม่หลุด

2. Mic ต้องใช้ send_realtime_input

เสียงสดจากไมค์ควรส่งผ่าน realtime input path ไม่ใช่ใช้ client content path ที่เหมาะกับข้อความหรือ content ที่ไม่ใช่ stream สด

3. แยก playback interrupt ออกจาก network

เมื่อ local VAD หรือ mic activity บอกว่าผู้ใช้พูดแทรก ให้หยุดเสียงที่กำลังเล่นใน client ทันที แล้วค่อย sync state กับ backend/model
