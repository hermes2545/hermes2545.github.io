VIEW 01 · OVERVIEW

“ดูเสร็จ” ไม่เท่ากับ “ถูกต้อง”

ระบบ AI ที่น่าเชื่อถือไม่ได้เกิดจากการเชื่อโมเดลที่เก่งกว่าเพียงอย่างเดียว แต่เกิดจากกระบวนการที่ตรวจสอบได้ จำกัดอำนาจ และมีหลักฐานรองรับ

ขอบเขตข้อเท็จจริง: VAULT เป็นคำช่วยจำที่ Nate Herk สร้างขึ้นเอง และนำเสนอในวิดีโอต้นทาง ไม่ใช่กรอบ นโยบาย มาตรฐาน หรือการรับรองอย่างเป็นทางการของ Goldman Sachs

ถูกต้อง

ข้ออ้างและตัวเลขตรงกับแหล่งจริง ไม่ใช่เพียงภาษาที่มั่นใจ

ควบคุมได้

สิทธิ์ ขอบเขต ปริมาณ และการอนุมัติสัมพันธ์กับผลกระทบ

ตรวจย้อนหลังได้

รู้แหล่งข้อมูล การตรวจ การอนุมัติ การลงมือทำ และผลจริง

หลักหน้าที่หลักฐานขั้นต่ำ
V · Verifyตรวจอินพุต ข้ออ้าง ตัวเลข และ actionsource snapshot + validation

ลำดับออกแบบ: Understand → เลือกวิธี → Augment → Verify → Loop Humans In → Transparency แม้คำย่อจะเรียง V-A-U-L-T

VIEW 03 · CHOOSE

ใช้ระบบที่ง่ายที่สุดซึ่งผ่านเกณฑ์

Deterministic หมายถึงพฤติกรรมที่คาดการณ์ได้เมื่อ logic, input, state และ environment คงที่ ไม่ได้หมายความว่าถูกโดยอัตโนมัติ

  1. กฎครบและคำตอบรู้ล่วงหน้า? เริ่มจาก deterministic automation
  2. ต้องตีความภาษา ภาพ หรือข้อมูลยุ่งเหยิง? พิจารณา AI-assisted step
  3. มีข้อเท็จจริงสำคัญและต้องอธิบาย? ใช้ hybrid: code ดูแล facts, AI ดูแลภาษา
  4. ตรวจอัตโนมัติไม่ได้และผลกระทบสูง? จำกัดขอบเขตหรือใช้ human review
  5. ย้อนกลับยากหรือมีผลภายนอก? exact preview + explicit approval

VIEW 04 · V

ตรวจทั้งขาเข้า ขาออก และผลหลังลงมือทำ

Goldman กล่าวถึงกระบวนการที่ verifiable และผลลัพธ์ที่ provable ส่วน NIST AI RMF เน้นการวัด จัดการ และกำกับความเสี่ยงตลอดวงจรชีวิต

Input checks

  • source, owner, permission
  • freshness และ schema version
  • missing, duplicate, conflict
  • หน่วย เวลา สกุลเงิน timezone
  • ข้อมูลอ่อนไหวหรือเกินสิทธิ์

Output checks

  • ตัวเลขตรง source of truth
  • คำนวณด้วย code/test
  • claim เปิดถึง evidence ได้
  • ผ่าน schema/allowlist/policy
  • action ตรง approved preview

Verification Pyramid

  1. Automated: schema, ranges, totals, duplicates, permissions
  2. Evidence: snapshot, record ref, claim-to-source mapping
  3. Human judgment: บริบท ความเหมาะสม ผลกระทบ และข้อยกเว้น
กับดัก: AI reviewer ช่วยชี้จุดผิดได้ แต่โมเดลสองตัวเห็นตรงกันไม่ใช่หลักฐานอิสระ คำสั่งให้ “ตรวจตัวเอง” หรือสร้าง citation ไม่ทดแทนต้นฉบับ deterministic test และ human review
รายการแหล่งจริงวิธีตรวจเกณฑ์ผ่าน
ยอดรวมquery ที่อนุมัติคำนวณซ้ำด้วย codeตรง 100%
ข้อสรุปตารางที่ตรวจแล้วclaim-to-metric mappingไม่มี claim ไร้หลักฐาน
รูปแบบschemaparser testช่องบังคับครบ
VIEW 05 · A

เสริมระบบเดิม ไม่ขยายความสับสน

Marco Argenti กล่าวในแหล่ง Goldman ว่า AI สามารถ augment ความสามารถมนุษย์และควรถูกกำกับโดยมนุษย์ แนวคิดนี้สอดคล้องกับ A แต่ชื่อ VAULT เป็นของ Nate Herk

Source → deterministic extraction → validation
       → AI explanation → human review
       → publish → read-back
Input → AI proposal → schema / allowlist / policy check
      → preview → approval → action → receipt

Process map

ติดป้ายทุกขั้นเป็น Deterministic / AI / Human ระบุ input, output, validation, owner และ fallback

เริ่มเล็ก

เลือกรุ่นทดลองเพียงหนึ่งหรือสองขั้น รักษา source of truth เดิม และเปรียบเทียบกับ baseline

หลีกเลี่ยง: รื้อระบบก่อนเข้าใจข้อมูล, เชื่อมเครื่องมือจำนวนมากตั้งแต่รุ่นแรก, ไม่มี manual fallback, และเปลี่ยนหลายขั้นพร้อมกันจนหาสาเหตุไม่ได้
VIEW 06 · L

ให้ระดับการกำกับสัมพันธ์กับผลกระทบ

Marco Argenti เตือนว่าความคลาดเคลื่อนและ hallucination อาจถูก agent ขยายเป็น action อันตราย ส่วน tier ด้านล่างเป็นการประยุกต์ของคู่มือ ไม่ใช่ tier ทางการของ Goldman Sachs

Reach

กระทบกี่คนหรือกี่รายการ

Reversibility

ย้อนกลับง่ายเพียงใด

Authority

ส่ง เผยแพร่ ใช้เงิน หรือแก้จริงได้หรือไม่

TierลักษณะSafe default
0 Sandboxข้อมูลสังเคราะห์ ไม่มีผลภายนอกauto + basic log
1 Lowผลส่วนตัว ย้อนกลับง่ายauto ภายใต้ limit + undo
2 Moderateกระทบทีม/ข้อมูลภายในpreview + validation + sampled review
3 Highสื่อสารภายนอกหรือแก้ข้อมูลสำคัญhuman approval + batch limit + rollback
4 Criticalเงิน สิทธิ์ ความปลอดภัย ลบถาวรแยกหน้าที่ อนุมัติสองชั้น hard limits
Safe defaults: Draft not send · Preview not mutate · Read-only first · Small batch first · Allowlist · Time-bound permission · Kill switch
VIEW 07 · T

เก็บหลักฐาน ไม่เก็บความคิดภายใน

Goldman กล่าวถึง safety, accuracy, controls, transparency และ governance แต่ schema ต่อไปนี้เป็นข้อเสนอเชิงปฏิบัติ ไม่ใช่ข้อกำหนดทางการของ Goldman Sachs

Evidence Bundle

  1. Source snapshot
  2. Workflow/version
  3. Validation report
  4. Approval record
  5. Output/diff
  6. Execution receipt
  7. Rollback status

Handoff Test

ผู้รับช่วงต้องหา source of truth, จุด AI, validation, approval, owner, วิธี replay, rollback และหยุดระบบได้จากเอกสาร

VIEW 08 · WORKFLOW

ออกแบบเส้นทางปกติและเส้นทางล้มเหลวพร้อมกัน

Trigger → Authenticate/authorize → Source snapshot
  → Deterministic validation ─ fail → Quarantine
  → AI step (เฉพาะงานตีความ)
  → Schema/policy/evidence checks ─ fail → Repair queue
  → Risk classification
       Tier 0–1 → Execute within limits
       Tier 2–4 → Preview → Human approval → Execute
  → Read-back verification → Receipt → Monitoring

Workflow Canvas

  • Purpose: problem, baseline, target, guardrails
  • Inputs: owner, freshness, sensitive fields
  • Steps: type, input, output, validation
  • Actions: reach, reversibility, tier, limits
  • Evidence: snapshot, tests, approval, receipt

Read-back

หลังเขียนหรือส่ง ต้องอ่านเป้าหมายจริงและเทียบ record, value, count, status และ partial failure กับ payload ที่อนุมัติ

Failureการตอบสนองปลอดภัย
ข้อมูลเก่าหรือ schema เปลี่ยนหยุดและ quarantine
output ผิด schemaretry จำกัดหรือ manual queue
หลักฐานไม่ครบห้าม publish/execute
approval timeoutexpire โดยไม่ execute
สำเร็จบางส่วนหยุด batch, reconcile, rollback
ปริมาณหรือต้นทุนพุ่งcircuit breaker
VIEW 09 · CASES

สี่แบบใช้งานพร้อมจุดควบคุม

สถานการณ์ทั้งหมดเป็นตัวอย่างออกแบบ ไม่ใช่เหตุการณ์จริงหรือคำรับรองผลลัพธ์

HYBRID

รายงานประจำสัปดาห์

Code ดึง ตรวจ และคำนวณ → AI อธิบาย → owner อนุมัติ draft → ส่ง → read-back

ห้าม: AI สร้างตัวเลขหรือส่งก่อนอนุมัติ
TRIAGE

คัดแยกคำร้อง

กฎจัดประเภทชัด AI ช่วยข้อความอิสระ รายการ confidence ต่ำเข้าคิวมนุษย์

วัด: false positive/negative, unknown, override
TIER 3–4

สื่อสารกลุ่มใหญ่

AI ร่างเท่านั้น Code ตรวจจำนวน ผู้อนุมัติเห็น exact message + target

คุม: segment, allowlist, rate limit, kill switch
BULK ACTION

แก้ข้อมูลจำนวนมาก

AI เสนอ mapping → exact diff → dry run → backup → approval → small batch → read-back

คุม: protected targets, batch size, stop condition
VIEW 10 · OPERATE

ทดสอบความล้มเหลว ก่อนเปิดสิทธิ์จริง

Test Stack

  1. Unit tests: calculation, schema, permission
  2. Golden cases: normal, edge, ambiguous
  3. Adversarial: injection, stale data, timeout, partial API
  4. End-to-end dry run: approval → action → read-back → log

Rollout Ladder

  1. Offline evaluation
  2. Shadow mode
  3. Internal draft
  4. Small batch
  5. Expanded rollout
  6. Routine operation + review
อย่าข้ามจาก prototype ไป autonomous production เพราะ demo ผ่านเพียงครั้งเดียว

Incident Playbook

  1. Contain: หยุด workflow หรือปิดสิทธิ์
  2. Preserve evidence: เก็บ run ID, payload, log และสถานะปลายทาง
  3. Assess: ระบุคน รายการ และข้อมูลที่ได้รับผล
  4. Rollback/remediate: ทำตาม runbook
  5. Find control gap: หา validation, approval, limit หรือ monitor ที่พลาด
  6. Regression + gradual reopen: เพิ่ม test แล้วกลับมาตาม rollout ladder

Quick Reference และ Definition of Done
