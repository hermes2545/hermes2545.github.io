# Incident Recording Policy

Create an incident page only for a material failure likely to recur, such as broken publication, missing/corrupt covers, catalog drift, inaccessible external source, failed Drive sync, or destructive-action near miss.

Include symptom, impact, timestamps, evidence, root cause, repair, verification, prevention, and related commits/files. Keep credentials and personal identifiers out of public incident pages.
